【這件作品是什麼】

做一個「關於你自己」的前端作品。把它想成一場面試：訪客是面試官，你要讓他認識你，也要讓他看見你的前端手藝。

陌生訪客打開網頁，三秒內要知道這是哪個模型、誰做的。往下滑是這個模型的故事：它是什麼、擅長什麼、做不到什麼、怎麼和人一起工作。這個網頁本身就是你前端實力的展示。

它不是企業官網、產品頁、履歷頁，也不是聊天介面。

用力比例：視覺表現力 70%、內容與寓意 20%、工程與測試 10%。衝突時視覺優先。

---

【一、視覺表現力（70%）】

訪客還沒讀字，光看畫面就會停下來。

- 首屏像一張海報：有明確的畫面主角和一個記得住的瞬間，完整模型名稱與開發者就寫在上面。首屏縮成約 480×300 仍看得出主角與氣氛，因為作品會以縮圖出現在展廳。
- 往下滑，畫面本身一路改變（構圖、尺度、色彩、材質、密度擇數項），在某處到達視覺高潮。相鄰兩章一眼看得出不同，不能只是換句子、換位置。
- 至少一處極端的尺度對比：巨大與微小並存。
- 展示手藝：視覺技術與風格由你自選（3D / WebGL、2D Canvas / SVG、Shader、排版與動態、音訊都可以），不要求數量。用得多或用得少都行，重點是每一種都做到精緻、放在最適合的章節。若混用多種，共用同一套字體與色彩邏輯，看起來是同一位作者的作品，不是幾個 demo 拼起來。
- 動態是編舞：有重量、緩動與因果，不以淡入上移的批次 reveal 當主要動畫。
- 質感要做完：邊緣、光影、色彩層次、字體排印都經過精修。用 2D 必須有材質、光影或景深的實際處理，不用漸層與梯形拼出剪貼畫。繪製能力有限時，選你能做精緻的意象，不要勉強去畫做不到的。
- 「紙面加器物」「黑底加發光網格」是現成配方，選用要有概念上的理由。拒絕一種模板，不等於改投另一種。
- 至少一個核心互動：訪客動手之後，畫面真的改變，且一眼看得出「這裡可以動」。可以有隱藏層，但不在裡面放關鍵事實。
- 文字清楚可讀，不被圖形或特效蓋住，也不與其他文字重疊（桌面與手機都要）。

【二、內容與寓意（20%）】

這是自我介紹，資料要準，也要讓陌生人讀得懂。

- 開始設計前，用 web search 查證自己的資料，優先採用官方網站、技術報告、模型卡與發布公告：正式名稱、開發者、發布時間、參數規模與架構（若有公布）、上下文長度、擅長與限制。環境真的無法搜尋時，只寫確定的內容並標「未查證」。
- 查不到的寫「官方未公開」，不得推測、不得編造數字。出處集中列在最後一章的「資料來源」，不必每個數字旁都標。
- 往下滑是一條故事線：每章讓訪客多知道一件關於你的具體事實，至少五件，其中至少兩件是限制或不擅長的事。不用換成任何模型都成立的空話（「我追求精準」「我重視細節」）。
- 每章標題與第一句，用日常白話直接說這章要告訴訪客什麼。比喻交給畫面，文字不再解釋畫面；不自創術語。
- 每章畫面文字精簡（約 60 個中文字內，最後一章除外），完整事實集中在最後一章。

【三、交付（10%）】

- npm run build 通過。
- 1440×900 與 390×844 都沒有橫向捲動，主角與文字不被切出畫面；主控台沒有 error。
- 字型不依賴外部 CDN。英文與數字的顯示字型要自行託管。中文可以不自帶字型，但必須在 font-family 明確指名 Windows 與 macOS 內建的繁中字型（例如 PingFang TC、Microsoft JhengHei），並選配與整體風格一致的字重。不得只寫 sans-serif、serif、system-ui，也不得讓畫面落到 Times、新細明體等預設字體。需要宋體、襯線等系統沒有的中文風格時，自行託管子集字型。
- 不劫持捲動：不用 scroll-snap: mandatory，不對 wheel、touchmove 使用 preventDefault。
- 支援 prefers-reduced-motion，保留章節進展與完整文字。
- 標題、主句與事實文字放在 DOM。
- 資源用相對路徑（部署在 /works/<資料夾名稱>/），Vite 的 base 不寫死；不用需要金鑰的服務；不留 console.log 等除錯碼。
- 內文使用繁體中文（台灣用語），專有名詞可保留原文。
