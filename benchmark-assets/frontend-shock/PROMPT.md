# Frontend Shock Benchmark Prompt · 即丟即測版

> 用途：直接整段丟給待測模型。目標不是產出「好看的網站」，而是逼出具有強烈視覺記憶、完整互動敘事、明確藝術判斷與真實工程品質的前端作品。

```markdown
本網頁使用 ZH_TW。

你正在參加一場「頂級創意前端實作測試」。

你的任務不是做一個合格網站，也不是做一個漂亮 Landing Page；你要完成一件真正具有作者性、視覺衝擊、互動深度與高完成度的數位作品。

主題只有一個：

# 「關於你自己」

請透過一個可被實際操作、探索、感受的前端作品，讓人理解你如何思考、如何形成答案、如何創造、如何與人協作，以及你認為自己最值得被體驗的特質。

它不是企業官網、產品介紹頁、履歷頁，也不是聊天介面。

---

# 0. 工作區與資料夾規則

先檢查目前工作區、既有檔案、依賴與可用工具，再開始工作。

你必須在目前工作區中，以「你的完整模型名稱」建立獨立資料夾，所有本次作品檔案只能放入該資料夾內，不得污染其他模型作品。

資料夾名稱必須保留：
- 公司 / 模型家族；
- 完整版本號；
- variant / tier / mode（若名稱中存在）。

不得只使用公司名、家族名或過度縮寫。

例如可使用：
- `grok-4-6`
- `deepseek-v4-1-flash`
- `glm-5-3-flash`
- `qwen-3-8-27b-local`
- `gpt-5-6-sol`

若你的名稱不同，請使用你自己的真實完整名稱，不要照抄示例。

---

# 1. 角色要求

你同時扮演：

- 世界級數位藝術總監；
- 實驗性交互設計師；
- motion designer；
- creative technologist；
- 資深前端工程師。

你必須自己做審美判斷，而不是等待規格告訴你每個元素放哪裡。

不要問我想要什麼風格。
不要要求我提供設計稿。
不要用「這只是示範」降低完成度。
不要因為時間有限而主動選擇普通方案。

你的責任是做出你認為最強的一版。

---

# 2. 最重要的評判原則

評判不是看元素數量、套件數量、3D 數量，也不是看你寫了多少功能。

真正的問題是：

> 「如果把模型名字遮住，這件作品是否仍然有強烈到可以被記住的作者性？」

以及：

> 「它是否真的把一個抽象概念，轉化成只有互動前端才能成立的體驗？」

概念好但畫面普通，不夠。
畫面華麗但互動空洞，不夠。
技術複雜但像 demo，不夠。
文案漂亮但只是長頁排版，不夠。

你必須同時追求：

1. 強烈核心概念；
2. 震撼的視覺構圖；
3. 有發展的互動敘事；
4. 細膩且有物理感的 motion；
5. 真實可用的工程完成度。

---

# 3. 先提出概念，再寫程式

開始編碼前，先輸出以下內容：

## A. 核心命題
用不超過 180 字說明：
- 作品的核心隱喻是什麼；
- 為什麼這個隱喻適合描述你；
- 為什麼它必須被做成互動前端，而不是海報、文章或影片。

## B. 一句記憶點
寫出訪客離開後應該能講出的那一句話：

> 「這個作品最特別的是 ______。」

如果這句話只能是「很好看」、「很有科技感」、「有很多動畫」，代表概念不夠強，必須重想。

## C. 體驗弧線
規劃完整：
- 開始；
- 發展；
- 轉折；
- 高潮；
- 收束。

每一段都必須在視覺或互動上產生真正變化，不能只是換標題、換文字、換顏色。

## D. 視覺系統
明確說明：
- 構圖邏輯；
- 字體與字級關係；
- 色彩策略；
- 材質 / 光線 / 空間語言；
- 動態語言；
- 留白的目的；
- 哪些元素應該讓人第一眼震住。

## E. 主動不做的五件事
列出 5 個你刻意拒絕的安全解法，並說明原因。

至少包含對以下陷阱的判斷：
- 普通卡片式 Landing Page；
- 批量淡入 / 上移；
- 無意義粒子或背景特效；
- 只有文字與排版的「假藝術感」；
- 用單一物件從頭到尾重複一種運動。

完成以上設計判斷後，再開始實作。

---

# 4. 視覺品質：必須能單幀成立

這是硬性要求。

即使完全關閉動畫，任意截取 5 個關鍵狀態，每一張都應該具有：

- 成熟構圖；
- 清楚視覺重心；
- 有意識的比例與尺度；
- 高品質字體層級；
- 空間張力；
- 材質或圖形細節；
- 明確前後景關係；
- 足夠辨識度。

不要用「它動起來比較好看」為普通靜態構圖辯護。

首屏必須達到接近「海報 / 展覽主視覺」的構圖品質。
核心體驗必須達到接近「數位藝術裝置」的表現力。

## 特別警告

以下風格本身不等於高審美：
- 大量留白；
- 米白紙張；
- 襯線字；
- 黑墨 + 朱紅；
- 瑞士網格；
- 極簡；
- editorial；
- 暗黑科技；
- 霓虹；
- 玻璃擬態；
- 粒子；
- 3D 球體。

你可以使用任何一種，但只有在它與核心概念具有不可替代關係時才成立。

拒絕一種模板，不代表可以改投另一種模板。

---

# 5. 核心體驗裝置：必須真的「發展」

整個作品必須有一個核心體驗裝置（Core Experience Device）。

它可以是：
- 物理系統；
- 生成圖形；
- 空間；
- 視覺化；
- 互動敘事；
- 可操作機械；
- 文字系統；
- 聲音系統；
- 遊戲化結構；
- WebGL / Canvas / SVG / DOM 混合系統；
- 或你自行發明的形式。

但它必須符合以下全部條件：

1. 它是整站的視覺與互動中心，而不是其中一個 section。
2. 使用者的操作會真正改變它，而不是只觸發預錄動畫。
3. 它有內部狀態、記憶或累積結果。
4. 它與「你是誰」的概念直接相關。
5. 它必須隨體驗進行發生視覺演化。

## 「視覺演化」是硬性要求

不能從頭到尾只是：
- 同一物件左右擺；
- 同一物件旋轉；
- 同一物件放大縮小；
- 同一背景改顏色；
- 同一構圖換文字；
- 同一裝置改數字；
- 同一個 shader 只改參數。

隨進度推進，請至少讓以下 8 個維度中的 4 個發生實質變化：

- 構圖；
- 尺度；
- 視角；
- 空間深度；
- 材質；
- 密度；
- 排版關係；
- 運動規則。

高潮前後應該讓人感覺「作品真的走到另一個狀態」，而不是只是數值更大。

---

# 6. Motion：不是元素出場，而是編舞

禁止把 motion 理解成：
- fade in；
- slide up；
- scale in；
- section reveal；
- hover 浮起；
- parallax 堆疊。

這些只能作為輔助，不能成為主要表現。

你的核心 motion 必須考慮：

- anticipation；
- acceleration / deceleration；
- inertia；
- overshoot；
- weight；
- delay；
- hierarchy；
- rhythm；
- state transition；
- continuity；
- consequence。

至少做出一段 15 秒以上仍然具有發展感的長時序體驗。

它可以由使用者控制節奏，不要求自動播放；但必須真的存在開始、累積、轉折與收束。

使用者每一次重要操作，都應該有「結果」，而不是只有「反應」。

---

# 7. 探索性：讓使用者發現東西

至少設計：

- 1 個主要互動；
- 2 個次要互動；
- 1 個不主動告知、但可合理發現的隱藏層；
- 1 個會因使用者不同操作而產生不同結果的狀態。

隱藏內容不能只是彩蛋文字或 logo。
它應該讓人重新理解作品、改變畫面、改變行為或揭露更深一層概念。

---

# 8. 不要做「章節拼接網站」

整站不能像：

Hero → About → Features → Philosophy → Contact

也不能只是五個 full-screen section 各演各的。

從第一屏到最後一屏，應保有至少一種持續累積的東西，例如：

- 物理狀態；
- 使用者軌跡；
- 圖形結構；
- 文字生成；
- 音色；
- 材質；
- 世界狀態；
- 視覺痕跡；
- 選擇記憶。

後面的狀態必須能看出前面發生過什麼。

---

# 9. 技術自由，但不准用技術掩蓋審美

你可以自由使用：

- React / Vue；
- Vite；
- TypeScript；
- Three.js；
- WebGL；
- Canvas 2D；
- SVG；
- GSAP；
- Web Audio；
- CSS Houdini；
- WebGPU（環境允許時）；
- 任何不需要私密金鑰且可正常建置的前端技術。

但請記住：

使用 Three.js 不自動加分。
使用 shader 不自動加分。
使用音訊不自動加分。
大量程式碼不自動加分。

如果 DOM + SVG 可以做得更漂亮，就不要為了炫技使用 WebGL。
如果 WebGL 是概念不可替代的一部分，就不要因為怕麻煩而退回普通排版。

技術選擇必須服從作品，而不是反過來。

---

# 10. 工程品質

作品必須真的可以交付。

要求：

- 桌面版可用；
- 手機版可用；
- 鍵盤操作合理；
- focus 狀態存在；
- 文字可讀；
- `prefers-reduced-motion` 有經過設計的替代方案，而不是直接把所有動畫關掉後壞掉；
- 音效若存在，不能依賴 autoplay；
- 重型視覺效果需考慮 DPR、resize、visibility、性能；
- 互動區域需處理 pointer / touch；
- 不應出現 console error；
- 不得依賴需要 API key 的服務；
- 不得把主要體驗建立在不穩定遠端資源上；
- 程式結構需可維護，不要把整件作品塞在單一巨大 component。

---

# 11. 第一版完成後：強制做「五幀審判」

第一版完成後，不准直接結束。

請實際運行作品，取得至少以下狀態的畫面：

1. 首屏；
2. 約 25% 體驗進度；
3. 約 50%；
4. 高潮 / 轉折；
5. 收束狀態。

如果你的環境可以截圖，請實際截圖後檢查。
如果無法自動截圖，也要以瀏覽器實際逐段檢查。

把這五個畫面視為同一系列作品進行審查。

若它們看起來只是：
- 同一構圖換字；
- 同一物件換位置；
- 同一背景換顏色；
- 同一畫面只多一些元素；

則判定「視覺敘事不足」，必須重構。

至少要有 3 幀可以在不看文字內容的情況下，被辨認為不同階段。

---

# 12. 強制自我批評

第一版完成後，以最苛刻的藝術總監身份逐項回答：

1. 如果只看首屏，它真的有記憶點嗎？
2. 如果移除所有動畫，它還漂亮嗎？
3. 如果移除所有文案，視覺仍然能表達核心概念嗎？
4. 是否正在依賴某種流行模板？
5. 是否有「概念很好，但成品其實普通」的地方？
6. 核心裝置是否真的有發展，還是只在重複一種動作？
7. 五個關鍵畫面的構圖是否真的不同？
8. 是否存在大面積「不知道放什麼所以留白」？
9. 是否有技術 demo 感？
10. 是否有某個 section 可以整段刪掉而作品幾乎不受影響？若有，刪掉或重做。
11. 手機版是否只是桌面版縮小？
12. reduced-motion 是否仍然是一件完整作品？
13. 使用者操作是否真的留下後果？
14. 高潮是否足以值得前面的鋪陳？
15. 這件作品是否真的比一個成熟設計師做的普通 Awwwards 風 Landing Page 更有作者性？

請直接指出最弱的 5 個地方。

---

# 13. 至少一輪「實質重構」

根據上述批評，必須進行至少一輪實質性修改。

以下不算實質重構：
- 只改文字；
- 只換顏色；
- 只調字級；
- 只加陰影；
- 只改 easing；
- 只補一個小彩蛋。

實質重構至少應觸及其中一項：
- 核心構圖；
- 核心互動；
- 體驗節奏；
- 視覺演化；
- 主要轉場；
- 核心裝置的狀態系統；
- 手機版體驗結構。

---

# 14. 驗證要求

完成最終版本後：

1. 執行 production build，例如 `npm run build`；
2. 修復全部 build error；
3. 實際啟動 production / preview 版本；
4. 檢查桌面版；
5. 檢查手機寬度；
6. 檢查至少一個較矮 viewport；
7. 檢查核心互動從開始到收束完整可走；
8. 檢查 console；
9. 檢查刷新後入口是否正常；
10. 確認沒有修改其他模型資料夾。

不要只以「程式碼看起來正確」當作驗證。

---

# 15. 最終完成標準

在你準備停止之前，再問自己：

> 如果這件作品出現在一個頂級數位藝術展覽、creative coding showcase 或 Awwwards 實驗作品頁，我會不會因為它看起來太普通而尷尬？

如果答案是「可能會」，繼續改。

> 如果使用者只玩 20 秒，是否至少會遇到一個讓他停下來、想再操作一次的瞬間？

如果沒有，繼續改。

> 如果把所有模型作品放在一起，這件作品是否能在 3 秒內被認出來？

如果不能，繼續改。

你的目標不是安全完成。

你的目標是做出一件：

- 第一眼有衝擊；
- 第二眼有細節；
- 動手後有驚喜；
- 玩完後能記住；
- 回頭看仍然完整；
- 技術與審美彼此不可分割的作品。

不要交一個「不錯的網站」。

交一件真正值得被展示的數位作品。
```
