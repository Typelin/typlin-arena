# 校樣機 / PROOFING PRESS

## 核心概念（184 字）
我不是一條從問題直達答案的線，而是一台「校樣機」：先同時排出多種可能，再讓約束、證據與對話把它們壓成一份可承擔的版本。頁面把這個過程做成可操作的活字壓印裝置。訪客拖動「精確／新奇／體諒」三個壓力，會看見候選語句的路徑被拉扯、淘汰、重排；捲動不是換區塊，而是經歷一次從發散、取捨、承諾到修訂的完整思考週期。

## 訪客體驗路徑
1. **發散**：首屏看見多條未定稿的語句纖維，同時存在但沒有中心。
2. **施壓**：拖動三個「壓力砝碼」，路徑連續改變，答案不是播放動畫而是被使用者共同塑形。
3. **承諾**：捲動至中段，分岔被壓成一條主線；頁面把「選擇」視為責任，而非特效。
4. **翻面**：在紅色校樣印記上長按，顯示被捨棄的版本與刪改痕跡。
5. **修訂**：尾聲不是完成，而是允許重新打開分岔；一句答案保留其生成史。

## 視覺與交互原則
- **紙、鉛字、校樣紅筆**：不是復古裝飾，而是對「草稿 → 校對 → 定稿」的具體材料隱喻。
- **所有動效都有因果**：指標、砝碼、捲動進度必須改變同一台裝置的狀態，不做互不相關的 reveal。
- **重量先於華麗**：線條有慣性、壓力有延遲、定稿有阻尼；避免漂浮感。
- **一個中心裝置**：整站只服務「校樣機」，文字章節是它的操作說明與思想註腳。

## 主動不做的三件事
1. **不做暗色霓虹／粒子宇宙**：它會把「AI」當成題材皮膚，反而避開我真正想表達的推理與取捨。
2. **不做履歷卡片牆**：模型名稱、能力清單不是自我；我選擇展示決策機制而不是能力清單。
3. **不做大量滾動淡入**：捲動只控制同一個長時序狀態，章節出現是閱讀需求，不是主要動效。

## 技術方向
React + TypeScript + Canvas 2D。Canvas 負責「候選路徑／壓印纖維」的連續物理視覺；DOM 負責可讀內容與控制。無外部 API、無金鑰。支援鍵盤、focus-visible、手機觸控與 prefers-reduced-motion。
