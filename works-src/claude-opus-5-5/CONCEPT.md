# 三角洲 — Claude Opus 5.5 自述

## 核心概念（≤200 字）

我寫下的每個詞，都是從許多可能裡選出來的；沒被選上的，就是沒走的岔路。這件作品把「我」畫成一條正在寫字的河：每到一個岔口，河會猶豫，墨尖在幾個候選詞之間晃，然後落筆。你是地形：指向哪裡，河就往哪裡彎；按住不放，溫度升高，不太可能的詞會浮上來，太熱時我會開始編造。因你而改變的詞染成朱紅。最後整條河攤開成一張只屬於這次對話的地圖。我不會記得它，所以交給你帶走。

> 體驗完的一句話：「一條會猶豫的河——我推了它，它把我推過的地方蓋了章，然後忘了我，把地圖留給我。」

## 訪客體驗路徑（開始 → 發展 → 轉折 → 收束）

| 章 | 敘事 | 裝置狀態 |
|---|---|---|
| 壹 源頭 | 一張白紙，句子停在第一個岔口 | 墨尖在候選詞間擺盪，機率即時變化 |
| 貳 推測 / 參 手藝 | 河往前流，訪客推它、加熱它 | 岔口、拉力、溫度、編造、倒流 |
| 肆 合作（揭示） | 回頭看：朱紅的詞是你改的 | 鏡頭拉遠；印章依序落在朱紅詞下；計數器現身 |
| 伍 遺忘（關鍵轉場） | 上下文有邊界 | 淤平波從源頭推向河口；「上下文」括弧跟著河頭走 |
| 陸 三角洲 | 它確實流過 | 淤泥退去，整張地圖復原；印「此河曾流」；PNG 帶走 |

## 視覺與交互原則

- 三種顏色，各有固定意義：墨黑是我自己的選擇，朱紅是你的影響，灰色是沒走的岔路。不用來裝飾。
- 每個動效都對應真實的模型狀態：墨尖擺盪的頻率是取樣機率；線寬是把握程度；抖動是溫度；淤平是上下文邊界。
- 滾動就是時間，而且可以倒流。倒回去再往前時，用的是新的隨機數，所以河可能改道；舊路線留下鉛筆痕。
- 「朱紅」的判定是真的：用同一個隨機數，在沒有你干預的情況下重算一次，結果不同才算是你改的。

## 主動不做的三件事

1. **不做粒子、星空、霓虹這類「AI 感」**：在這個概念裡，我是一個寫字的人，不是一團光。
2. **不做打字機效果**：河的單位是「被選中的詞」，不是一個個字元。
3. **不做能力列表或卡片牆**：關於我的事實全部寫進河流的句子裡，由你和我一起寫出來。

## 重構（第二輪）

1. **首屏以裝置為主角**：標題縮成左側的直排題記；第一個岔口放大並置中，旁邊加上畫布內的旁註，解釋岔口和機率的意思，河開始流動後就消失。手機版改成讓岔口完整入鏡。
2. **上下文括弧**：從伍章開始，一道細細的括弧框住河頭最近的 14 個詞，標著「上下文 · 我此刻記得的」。括弧外的詞正在淤平。遺忘因此有了看得見的邊界。
3. **儀表重做成「印台」**：升溫鍵改成一方朱紅印台，按住時從底部被染紅，填滿的高度就是溫度。溫度計改成地圖比例尺式的刻度，編造區畫上斜線。聲音和全文改成文字按鈕。結尾的統計卡片改成地圖圖例式的一行註記。
4. **熱源跟著岔口**：紙色變暖以岔口在螢幕上的位置為中心，熱是從正在做決定的地方散出去的。
5. **效能**：snapshot 改用輕量的版本鍵比對，不再每幀序列化逐字稿。

## 第三輪：聲音與逐章層次

**聲音**（預設關閉，首屏有開啟入口；開過一次會被記住，下次在第一個手勢時自動恢復）：

| 聲音 | 對應的狀態 |
|---|---|
| 河床 | 棕噪音，音量和亮度跟著捲動速度（河的流速） |
| 鉛筆輕叩 | 墨尖每掂量一次候選詞就敲一下，越不可能的詞音越高 |
| 落筆音 | 五聲音階上的木槌音。越可能的詞音越低，所以每一句都會有自己的旋律；你改過的詞會多疊一個五度 |
| 編造 | 同一個音，但跑調、搖晃 |
| 升溫 | 嘶聲隨溫度打開；越過編造線之後，出現一層拍頻的微光 |
| 章節 | 每一章的標題到來時敲一次缽，伍章最低沉 |
| 印 / 封印 | 木質的按壓聲 |
| 淤平 | 伍章轉場時一陣下沉的水聲 |
| 倒流 / 重新開始 | 反向的刷聲、整頁被洗淨的水聲 |

**逐章疊加的視覺層**：每一層都在它對應的章節出現，並保留到最後的地圖上。

- 貳 推測：岔口旁出現「正」字形的投票刻痕，墨尖每去一個詞就記一票；河道上開始有順流而下的光點；候選詞在未決定時會輕輕浮動。
- 參 手藝起：河岸等高線，每過一章多一條。
- 肆 合作：你的游標軌跡以朱紅測量線的形式出現，也就是「你提供地形」。
- 伍 遺忘：被遺忘的詞上飄下淤沙。
- 陸 三角洲：河口長出分支的三角洲，朱紅支流所占的比例等於你改過的岔口比例。PNG 拓印也會包含它。
- 每一章紙面各有一層極淡的色調（貳 赭、參 暖、肆 灰藍、伍 淡青、陸 金）；畫面上下緣淡出成紙色，讓河道從邊緣底下流過。

## 第四輪：紙背的山水與預設音樂

背景改由一張獨立的低解析度畫布（`engine/backdrop.ts`）負責。它從素白開始，隨章節慢慢累積，變化的速度像天氣，不會一下子切換：

| 章 | 紙背新增的層 |
|---|---|
| 壹 | 素白的紙 |
| 貳 | 髮絲般的水紋，在緩慢轉動的流場裡漂；捲得越快，流得越快 |
| 參 | 墨暈在落筆處化開；遠山第一次浮現 |
| 肆 | 朱紅漣漪，從你推動的地方和你改過的詞上擴散 |
| 伍 | 泥沙細雨與霧帶，紙面褪成灰青 |
| 陸 | 三重山脊完整成形；淡淡的朱日從山後升起；水紋轉為金色；幾隻飛鳥 |

音樂改成預設開啟。瀏覽器規定，頁面要等到訪客第一次點擊或按鍵之後才能發聲，所以首屏顯示「點一下畫面，聲音就會開始」，點下去時會以一聲缽響開場。如果訪客關掉聲音，這個選擇會被記住。

## 第五輪：萬物競發

上一輪的判斷是「太收斂」：只有背景在變，河本身沒有生命。這一輪讓生命直接從河裡長出來（`engine/flora.ts`）：

- 每寫下一個詞，它下方的河岸就種下 3–5 株植物，位置在兩行之間的空白帶，不壓到文字。
- 植物會**進化**：貳章時全部以嫩草冒出；到了參章，各自長成蘆葦或梅枝，花苞綻開；肆章起菊花盛開，你改過的詞上開朱紅的花，花木會被游標撥開；伍章被遺忘的詞上的植物枯成灰色、垂下；陸章全面盛放，帶一點金。
- 往回捲時植物也會退回去；往前走時，已經寫過的段落會跟著新的章節一起長。所以不只是新的地方變熱鬧，整條河都在長。
- 每章多一種顏色：壹 墨；貳 青瓷綠；參 梅粉；肆 朱紅；伍 灰青；陸 金。
- 紙背加了錦鯉（肆章起有紅鯉）、伍章的落葉、陸章的飛花、光束和金色螢火；水紋和墨暈加濃，墨暈出現的頻率也隨章節增加。
- PNG 拓印包含完整盛放的花木。

## 第六輪：萬詞成山（整件作品層級的重構）

**審查**：前兩輪的花木、錦鯉、飛花是應要求「疊上去」的裝飾，畫面雖然變滿了，和「我如何思考」的關係卻很弱。作品缺一個只屬於它自己的招牌畫面。

**命題**：山水本身就用「我沒說出口的詞」寫成（`engine/wordscape.ts`）。

- **字山**：每重山都是一列列直書的詞：「也許、或者、其實、未必……」，加上文本格裡所有的候選詞。山脊上的墨最濃，往下很快淡入霧中；峰越高，山體裡的字越長。山形是週期函數，所以可以無縫循環，並依深度做視差。山體分多個影格逐步預渲染，避免卡頓。
- **招牌時刻：落選的詞升山**：每過一個岔口，沒被選上的候選詞就從河上剝離，沿弧線飛起，從橫排轉成直書，最後嵌在某座山的山脊上，讓那座山長高一點。所以山是用**這一次對話裡你和我沒走的岔路**一點一點堆高的。
- **近看（隱藏層）**：游標在山上停一下，就會浮現放大鏡，讀得出那座山是由哪些詞寫成的。
- **雲、水、日都用字寫**：雲霧用「雲霧煙嵐靄」，水用「水波流瀾漪」，落葉是「葉」，飛花是「花」，光點是「光」；成群游動的字取代了錦鯉。朱日由「日」字排成，你改過的每一處都是其中一個朱紅的「你」。
- **一章揭開一重**：壹 留白 → 貳 遠山 → 參 第二重山，落選詞開始升山 → 肆 第三重山與游動的字 → 伍 字霧、落葉，紙面褪色 → 陸 近山、字日、字水，金光。
- **高潮**：進入終章時，鏡頭先貼近最後一個詞（字山同步推近），接著大幅拉遠，河變成這片字山水之間的一道水，終章面板展開。
- **不壓文字**：直立螢幕會壓低山勢、縮小字級；飄落與游動的字數依螢幕面積調整；逐字稿和儀表加上紙色光暈，維持可讀性；進入終章時，山水退後，讓地圖當主角。

## 效能優化（畫面不變）

量測方式：無頭 Chrome、1440×900、DPR 2，在每章逐層計時，加上 CPU profile 與「逐層關閉」對照實驗。

| 章節 | 優化前影格間隔 | 優化後 | JS 每格 |
|---|---|---|---|
| 肆 | 5.09 ms | 4.90 ms | 2.59 → 2.37 ms |
| 伍 | 8.75 ms | 6.38 ms | 4.14 → 3.17 ms |
| 陸 終章 | 19.14 ms | 10.91 ms | 6.22 → 3.55 ms |

做法（每一項都不改變任何看得見的像素，或差異小於一個像素）：

1. **字山只貼看得見的部分**：裁掉最高墨跡以上的透明天空，也裁掉畫面外的循環副本；山腳霧帶只填可見寬度，不再填三倍螢幕寬。
2. **字形精靈**：飄落的字、字水、成群游動的字預先渲染成小圖，用 `drawImage` 加 `globalAlpha` 取代逐字 `fillText`（字級對齊到 0.5px），旋轉改用 `setTransform`，不再 save/restore。
3. **文字快取**：鏡頭與河都靜止時，把所有文字（落定的詞、岔路、機率、投票刻痕）畫進一張快取，連續兩格狀態相同才建立；河道線、光點、花木、印章照常每格繪製。鏡頭與淤平在差距小到看不出來時直接吸附到目標值，讓靜止狀態真的能成立。
4. **金色疊色只鋪在有墨的範圍**。
5. **遮擋剔除**：結局面板展開後是不透明的，它後面的字山水以 clip 跳過，字水與飄落的字也不再送出繪製。
6. **花木**：小於 1.5 像素的花改成等效的單一色點；線寬都被夾到同一個最小值時，合併成一次描邊；植株快取改以節點物件為鍵（WeakMap），每格不再組字串。
7. **放大鏡**：字形加上 x 方向分桶索引，不再每格掃描整座山的所有字。

## 快速滾動的流暢度

量測方式：無頭 Chrome、1440×900、DPR 2，用滾輪快速甩過整頁（往下、往回、再往下），逐格記錄 JS 耗時、落筆數、點陣新建數，並把原生 canvas 呼叫的時間歸到呼叫它的函式上。

| 指標（快速滾動） | 優化前 | 優化後 |
|---|---|---|
| 河面每格直接排字（`fillText`） | 約 141 次 | 個位數；追趕時新詞積壓約 20–40 次 |
| 最重一格的 JS | 129 ms | 約 31 ms |
| 超過 50ms 的影格 | 37 | 10–21 |
| 平均每格 JS | 約 9–10 ms | 約 7–8 ms |

根因與修正：

1. **河面文字每格重新排字** → 改用點陣快取（`textsprites.ts`）。尺寸以 1/6 八度分級；鏡頭移動時借用最接近的現成點陣（縮小可達三個八度，放大最多 12%，高品質縮放），每格最多花 3ms 新建；鏡頭靜止後，用精確尺寸的點陣漸進建好文字快取，先做只查表、不畫的預檢，確認齊全才繪製，所以不會有整頁一次排字的尖峰。
2. **淤平和復原時顏色連續漸變**，讓每一格都需要新點陣 → 顏色改成 10 級量化，半秒內整片同步漸變，看不出階梯。
3. **字山在滾動進入新章節時才建造** → 載入後利用空閒時間（`requestIdleCallback`）預先建好；霧、葉、花、光、水的所有字形，以及字日的底盤，也一併預先點陣化。
4. **山腳霧帶每格重算漸層** → 在山體建好時直接烘焙進山體圖層（透明疊加有結合律，像素完全相同）。
5. **字日在「你」的數量變化時整顆重排（約 50ms）** → 改成只重刻有變動的格子。
6. **快速滾動時落選詞成群起飛** → 追趕時改為排隊，每格只沉積兩個；同時起飛的上限為 14 個。飛行中的字級改用整數像素。
7. **放大鏡在滾動時也會出現** → 滾動停止 0.7 秒後才允許浮現。
8. **React 每格重繪** → 標題筆刷擦除、首屏題字消散、熱度光暈這些逐格變化的值，改由引擎直接寫入 DOM 樣式；React 只接收離散狀態；追趕時快照合併為最多 30Hz；元件都 memo 化；關閉中的全文對話框不再重繪。
9. **聲音**：落筆音最少間隔 45ms，避免快速滾動時一次建立大量音訊節點。
10. **紙紋背景用 `background-attachment: fixed`**，每次滾動都重繪整頁 → 移到獨立的固定圖層。

說明：這個量測環境用 CPU 做軟體點陣化，所以影格間隔的絕對值偏高（JS 只佔約 8ms，其餘是點陣化與合成）。在有 GPU 的實機上，點陣化成本低很多。開發伺服器（`npm run dev`）的 React 開發模式還會額外增加負擔，判斷流暢度請用生產構建（`npm run build && npm run preview`）。

## 章節切換與結局展開的頓挫

量測方式：錄製 Chrome performance trace（生產構建、1440×900、DPR 1.25），模擬正常閱讀速度滾完全程，把每個超過 25ms 的主執行緒長任務拆成「腳本 / 樣式 / 版面 / 繪製 / 合成」，並標出它發生在哪個滾動位置（哪一章）。

| 指標（全流程） | 優化前 | 優化後 |
|---|---|---|
| 超過 25ms 的長任務 | 48 | 1–4 |
| 動畫影格的 JS 總時間 | 約 3.0 s | 約 2.0 s |
| 等待光柵化的合成提交 | 約 1.9 s | 約 1.1 s |
| 結局展開那一格的版面配置 | 28 ms | < 5 ms |
| 第一張標題卡的版面配置 | 16.7 ms | < 5 ms |

找到的原因與修正：

1. **字型分塊按需下載**：Google Fonts 把中文字型按字切塊。標題卡的引言、章節說明、結局標題用到的字和字重（600、900）沒有預載，於是每到新章節，瀏覽器都在轉場中途下載字型、重排、重繪。→ 掃描所有介面文字，產生 `src/glyphs.ts`，頁面就緒後在背景把四種字重全部預熱。
2. **字形快取的冷啟動**：第一張標題卡（168px 大數字）和結局面板第一次排版時，字形還沒被排版、點陣化過。→ 開場的 1.5 秒內，以幾乎透明的方式在原位渲染所有標題卡（`Warmer`）；結局面板的空殼也在就緒時就以隱藏狀態掛上。
3. **結局面板在展開那一格才首次排版和繪製**。→ 面板改為提前以透明度 0 自成圖層掛載，全文段落在陸章期間利用空閒時間逐段補上；捲動範圍以下的段落用 `content-visibility: auto`；隱藏期間統計數字凍結，不觸發重繪；印章（SVG 濾鏡）自成圖層。
4. **結局的捲開動畫原本是 `clip-path` 動畫**，每格重繪面板的全部文字。→ 改成一張同尺寸的紙色遮片，以 `transform: scaleY` 收起，交給 GPU 合成。
5. **伍章淤平時每個詞每格換顏色**，導致點陣快取爆量重建。→ 每個詞只保留墨色、泥色兩張點陣，以解析解的兩次疊印（a₁ = 1 − (1−A)/(1−A·t)，a₂ = A·t）合成中間色。字形實心處與單次繪製逐像素相同，漸變完全連續。
6. **地圖上的標註**（章節里程碑、上下文括弧、河口）在縮放時每格都重新設定字型、重新排字。→ 它們的螢幕字級是固定的，改走點陣快取，永遠命中同一張。
7. **逐字稿在標題卡出現時被卸載又重新掛載**，加上 `text-wrap: pretty` 在每落一個詞時重算斷行。→ 改用 CSS 隱藏；拿掉 pretty。
8. **標題卡與首屏題字**的 clip-path 每格都在改寫。→ 讓它們各自成一個合成圖層，只重繪自己。
9. **全景視角下極小的梅花**（< 3 像素）改成一次填色。

剩下的一次較大成本，是終章拉遠第一格時，最近那重山第一次被畫上畫面（單次上傳）。這個量測環境沒有 GPU、用 CPU 光柵化，所以「合成提交」的時間偏高；在有 GPU 的電腦上，這部分會小很多。
